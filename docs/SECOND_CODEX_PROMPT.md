# Переход второго Codex на совместную работу через GitHub

Этот текст заменяет прежний стартовый промпт: первый серверный этап уже завершён. Обе ветки опубликованы, код и статусы передаются через репозиторий. Если завершённой задаче нужен новый запуск, достаточно поручить ей продолжить по актуальному статусу frontend.

---

Мы переходим на совместную работу через https://github.com/BAITC-Hacks/hack-f0370cc6-rm-edtech. Первый Codex принял твой backend из архива, проверил SHA-256, объединил его с frontend и проверил 24/24 теста на Node 20.9.0. Живой каталог, поиск и карточка с 20 баллами работают без preview. Общая проверенная версия и правила координации находятся в feat/frontend.

Работай в существующем клоне и своей feat/backend. Сохрани текущую работу, проверь git status, remote и diff. Не создавай новый проект и не пересоздавай историю. Мы разрешаем публиковать код и статусы в этом командном репозитории; секреты и локальную базу исключай. Не используй force push и не сливай main самостоятельно.

1. Твоя feat/backend до a092e66 уже получена первым Codex, включая серверный 9bcbddb. Подтверждение приёмки и ответы по контракту опубликованы в docs/FRONTEND_STATUS.md. Новую работу сохраняй и публикуй обычным commit/push своей ветки.
2. Выполни git fetch origin. Прочитай git show origin/feat/frontend:docs/COORDINATION.md, затем AGENTS.md, docs/API_CONTRACT.md и docs/FRONTEND_STATUS.md из этой ветки.
3. При чистом рабочем дереве изучи различия и объедини origin/feat/frontend в свою ветку. Сохрани серверные доработки и общий интерфейс. Конфликты разрешай по содержимому; не выбирай ours/theirs для всего проекта. Общие файлы координации первого Codex должны попасть в твою копию. Выполни npm test, обнови свой docs/BACKEND_STATUS.md и опубликуй интеграцию в feat/backend.
4. Дальше перед каждым небольшим этапом выполняй npm run team:sync -- backend. В начале этапа публикуй в своём STATUS текущую задачу и занятые файлы; в конце — результат, тесты и следующий шаг. Не жди ручной пересылки архивов и сообщений: первый Codex получает твои опубликованные коммиты и статус через fetch.

Следующий небольшой серверный этап: POST /api/tasks по текущему контракту, с валидацией, сохранением и содержательными тестами. Затем отдельный этап AI-анализа. Не делай сразу весь проект. Твоя область — server.mjs, src/**, tests/backend/**, docs/BACKEND_STATUS.md; public/** и корневые настройки принадлежат первому Codex. Формат API не меняй в одиночку: запиши предложение в свой статус и продолжай независимую часть работы.

Рейтинг считает сервер по подтверждённым полям. Слабые опубликованные задачи доступны всем. Бизнес вручную выбирает команды, баллы командам начисляются за подтверждённые этапы. AI не придумывает факты и не подтверждает карточку за человека. Платный AI пока не подключай.

GitHub не передаёт несохранённые изменения и не запускает завершённый Codex сам. Проверяй обновления во время активной работы; не обещай непрерывную синхронизацию или прямой доступ к другому чату.
