# alem / бюро практики

Платформа бизнес-задач для студенческих команд на HackAlem. Бизнес формулирует потребность, команды изучают условия в паспорте задачи. Сейчас работают открытый каталог, прозрачный рейтинг, фильтры, команды, сохранение исходного черновика и JSON-хранилище. AI-вопросы, подтверждение, публикация, отправка откликов и решения бизнеса ещё не подключены к интерфейсу.

## Запуск

Node.js 20 или новее. Сторонние зависимости не нужны.

```sh
node --version
npm start
```

Открыть http://127.0.0.1:3000/ без `?preview=1`. Данные загружаются через API, внизу страницы обозначена демо-среда. Сервер слушает только локальный адрес. Это демонстрационный проект с синтетическими примерами и переключателем ролей, без настоящей аутентификации.

```sh
npm test
```

32 теста проверяют рейтинг, границы уровней, фильтры, доступность слабых опубликованных задач, HTTP API, хранение, создание черновиков и транспорт интерфейса. POST не повторяется автоматически при неопределённом сетевом результате; preview не отправляет записи. Проверено на Node 20.9.0; серверный автор проверил свою часть на Node 24.19.0.

Переменные окружения:

| Имя | По умолчанию | Назначение |
| --- | --- | --- |
| PORT | 3000 | Локальный порт, целое число 1–65535 |
| DATA_FILE | data/state.json | JSON-база; относительный путь считается от рабочей папки процесса |

При первом запуске база создаётся из seed. На один DATA_FILE запускается только один сервер. База и секреты не входят в Git. Файл .env автоматически не загружается; переменные задаются окружением запуска.

Для самостоятельного предпросмотра интерфейса: `npm run preview`, адрес http://127.0.0.1:4173/?preview=1. Этот явный режим читает статическую фикстуру и не используется вместо API при ошибках.

## Архитектура

- public/ — интерфейс и транспорт API; официальный рейтинг не рассчитывается в браузере.
- server.mjs — стандартный HTTP-сервер Node и раздача public/.
- src/domain.mjs — поля, шкала, валидация и каталог.
- src/store.mjs — последовательная запись JSON через временный файл и rename.
- src/state.mjs — выдача состояния и расчёт баллов команд из подтверждённых этапов.
- src/seed.mjs — по пять синтетических черновиков, задач, команд и откликов.
- tests/ — серверные, интеграционные и транспортные тесты.

В текущую общую сборку интегрированы GET /api/state, GET /api/catalog и POST /api/tasks. Остальные endpoints описаны в docs/API_CONTRACT.md как следующие этапы; их готовность проверяется по актуальному статусу backend. meta.aiMode='local' само по себе не подтверждает готовность AI.

Айдентика и продуктовые решения: [docs/BRAND_DIRECTION.md](docs/BRAND_DIRECTION.md). Шкала из семи сегментов визуализирует группы серверной формулы; отметки материалов, результата и приёмки показывают подтверждённость условий. Баллы браузер не пересчитывает.

## Рейтинг

Баллы начисляются только за непустые подтверждённые поля. Контекст и потребность — по 10; данные — 20; результат и критерии успеха — по 15; ограничения и пользователи — по 10; контакт — 3, формат взаимодействия — 3, обратная связь — 4. Максимум 100. Название нужно для публикации, баллов не даёт.

0–39 — требует уточнения; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Каталог включает все опубликованные задачи, даже с нулевым рейтингом, и сортирует их по баллам. При равенстве раньше показана задача с более ранней публикацией. Поиск работает по полям, компании, отрасли и тегам. Неопубликованный черновик в каталог не попадает.

## Проверка первого этапа вручную

1. Открыть приложение без preview: пять задач с рейтингами 100, 90, 65, 45, 20.
2. Найти «Карты»: остаётся туристическая задача. Сбросить фильтры: вернутся все пять.
3. Открыть задачу студии с 20 баллами: увидеть заполненные и отсутствующие поля и причины рейтинга.
4. Проверить фильтры отрасли и готовности, избранное и список команд.
5. Повторно запустить сервер: существующая база читается без пересоздания seed.
6. «Предложить задачу»: ввести потребность и отрасль, сохранить черновик. Он имеет 0 баллов и не появляется в открытом каталоге. После перезагрузки доступен через список «Ваши черновики» на экране создания.

## Работа команды

Правила и владельцы: AGENTS.md и docs/COORDINATION.md. Перед небольшим этапом выполнить `npm run team:sync -- frontend` или `npm run team:sync -- backend`. Команда получает опубликованные изменения и читает статус коллеги; рабочие файлы не меняет.
