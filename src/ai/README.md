# Анализ потребности: локальные правила и OpenAI API

POST /api/ai/analyze принимает `{raw,industry,fields?,answers?}` и возвращает `{mode,fields,questions,missingFields,warnings}`. Схема API v1 сохранена. Анализ не сохраняет задачу, не подтверждает сведения и не начисляет рейтинг. Подтверждение и публикация выполняются отдельными endpoint.

## Два режима

- Без серверного ключа — `mode=local`: правила и шаблоны из local.mjs, без сети. Промпт для объяснения режима — prompt.mjs; заглушка не исполняет его моделью.
- С ключом — OpenAI Responses API. Модель формулирует 3–6 вопросов по описанию задачи и уже введённым сведениям. Успешный ответ — `mode=remote`. Промпт и строгая схема — openai.mjs.
- При ошибке внешнего сервиса, отказе, незавершённом/неверном ответе или таймауте — `mode=local`, локальные вопросы и предупреждение о неуспешной попытке внешнего анализа. Ошибочный ввод пользователя остаётся 400.

Модель генерирует только вопросы. Поля карточки собирает сервер из данных человека: непустой answers[field] заменяет fields[field], пустой ответ не стирает; raw копируется в context только при отсутствии context в fields и answers. Явно пустой context остаётся пустым. Это согласованная с frontend семантика, а не автоматическое извлечение всех фактов из свободного текста. AI-оформление портфолио и анализ откликов сюда пока не входят.

## Настройка

В корне проекта создайте локальный `.env` (он исключён из Git) либо задайте переменные окружения:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini
```

Вставьте проектный ключ после OPENAI_API_KEY= в локальном файле и сохраните его. Не присылайте ключ в чат и не добавляйте в исходный код. Перезапустите сервер (`npm start`, Node 20+), чтобы применить настройки. Приоритет у окружения процесса; пустая OPENAI_API_KEY в окружении явно отключает remote. Поддержаны простые строки, кавычки и комментарии; shell-подстановок нет. Произвольный URL или модель из HTTP-запроса не принимаются.

Соединение прямое: https://api.openai.com/v1/responses. Модель по умолчанию gpt-4.1-mini; доступ и баланс зависят от проекта OpenAI. Инструкция хакатона разделяет подписку ChatGPT и API-кредиты: наличие подписки не подтверждает доступность API. Персональная ссылка/промокод выдаются на платформе хакатона или в Telegram-боте; сначала активируйте API Credits.

Ключ читает только CLI запуска через config.mjs. createApplication() в тестах не загружает .env и не вызывает провайдера автоматически. Для тестов передаётся analysisOptions с подставным fetch. Не печатать конфигурацию целиком в логи.

## Проверки и ограничения

Внешний вызов: общий таймаут 15 секунд с AbortSignal, до 3000 выходных токенов, до 64 КиБ тела ответа, без автоматических повторов и переадресаций. В запросе store:false. Это параметр хранения Responses, не обещание отсутствия любых служебных журналов провайдера.

Ответ ограничен JSON Schema. Сервер дополнительно проверяет 3–6 уникальных известных field, непустые вопросы/причины с лимитами, отсутствие лишних ключей. Поля, missingFields, mode и warnings определяет сервер. Модель не имеет доступа к хранилищу, ключам или инструментам. Structured Outputs ограничивает формат; смысловую уместность вопросов проверяет человек.

meta.aiMode=remote означает настроенный внешний режим, а не гарантированную доступность провайдера. UI использует mode и warnings конкретного ответа. Ошибки провайдера, его диагностическое тело и ключ пользователю не возвращаются.

Проверки: npm test. remote-ai.test.mjs использует подставные ответы, покрывает корректный запрос, ошибки, отказ, схему, таймаут/отмену и лимиты. HTTP-анализ не меняет память и DATA_FILE. Реальный вызов с ключом проверяется отдельно; успех нельзя выводить из unit-тестов. examples.json содержит локальные примеры, а не ответы внешней модели.
