# Локальный анализ потребности: этап AI

Это **локальная заглушка на правилах и шаблонах**, а не LLM. Сеть, API-ключи и платные сервисы не используются. Такой режим разрешён исходным ТЗ при демонстрации промпта, входа/выхода и обработки неправильного ответа. Промпт открыт в `prompt.mjs`, но заглушка не исполняет его моделью: он фиксирует ожидаемое поведение для демонстрации и будущей интеграции.

## POST /api/ai/analyze

Тело JSON: `{raw, industry, fields?, answers?}`. Raw — непустая строка до 4000 символов, industry — из meta.industries. Fields/answers — объекты известных полей со строками и лимитами FIELDS. Неизвестные ключи и неверные типы отклоняются. Анализ не принимает taskId, не сохраняет задачу, не выставляет рейтинг, не подтверждает и не публикует карточку.

Ответ 200: `{mode:"local", fields, questions, missingFields, warnings}`. В fields все 11 полей. Questions — 3–6 разных вопросов `{field,question,reason}`. MissingFields отражает пустые поля, включая title, а не подтверждение. Warnings обязательно сообщает, что использована заглушка. Ошибки входа — 400, методы кроме POST — 405, большой JSON — 413 (общий предел 64 КиБ).

## Как сохраняются факты

1. Введённые поля очищаются от крайних пробелов и сохраняются. Непустой answers[field] считается последним уточнением человека и заменяет fields[field]. Пустой ответ не удаляет существующие сведения.
2. Только если context вообще не передан ни в fields, ни в answers, raw дословно помещается в context. Для очистки передайте fields.context="" без непустого answers.context. Пустой answers.context не стирает существующий fields.context; непустой ответ имеет приоритет. Это перенос исходного текста, не семантическое извлечение сведений.
3. Даты, контакты, критерии и другие факты из свободного текста не угадываются. Для заполнения нужно явно ввести соответствующие поля или ответы. Слова «не знаю» остаются словами пользователя: заглушка не проверяет их полезность или достоверность.
4. Вопросы выбираются по пропущенным сведениям: данные, успех, результат, ограничения, пользователи и далее остальные поля. Для нескольких отраслей вопрос о возможных материалах конкретизирован, без утверждения, что они существуют.
5. Если пропусков меньше трёх, добавляются вопросы проверки заполненных сведений. Полностью заполненная карточка получает три вопроса проверки и missingFields=[].

Все эти детали — реализация в рамках прежней схемы. В BACKEND_STATUS они переданы владельцу frontend для согласования семантики с формой. Ответы анализа нужно показывать в редактируемом виде; официальное сохранение/подтверждение относится к следующему endpoint.

## Проверка результата и безопасный ответ при ошибке

Анализатор получает копию входных данных и возвращает JSON-строку. Граница проверяет размер, точный набор верхних ключей, 11 строковых полей, отсутствие изменений/добавлений к разрешённому локальному набору фактов, 3–6 вопросов с известными уникальными field, missingFields и warnings. Это проверка конкретного локального режима, не универсальный детектор галлюцинаций и не готовый адаптер внешней модели.

Неправильный JSON, схема, утрата человеческого поля, выдуманное поле, ошибка генератора или превышение 2 секунд дают заново построенный локальный ответ с дополнительным предупреждением. Текст исключения и потенциальные секреты не возвращаются. Ошибка входных данных остаётся ошибкой HTTP 400 и не превращается в успех.

Проверки ошибок используют внедрённый генератор через параметры конструктора сервера/модуля. По HTTP нельзя выбрать генератор, URL или режим remote. Ограничение времени покрывает асинхронный ответ; синхронный бесконечный цикл в том же потоке оно не прерывает. Текущий генератор ограничен размерами ввода и не имеет произвольных циклов.

## Демонстрация

`examples.json` содержит слабое описание и повторный проход с ответами, с фактическими ответами текущей реализации. Проверка: `node --test tests/backend/ai.test.mjs tests/backend/http.test.mjs`. Тесты показывают неправильный JSON, неверную схему, потерю фактов, исключение/таймаут, сохранность данных и отсутствие изменений базы.

Учебный вопрос: если анализ вернул заполненное поле data, изменится ли рейтинг сохранённой задачи? Нет: анализ только предлагает значения; необходим отдельный шаг ручного подтверждения и сохранения. В этом этапе такой endpoint ещё не реализован.
